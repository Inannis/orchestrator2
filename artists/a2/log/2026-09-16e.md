## Second addendum, same session: the whole specificity/charge frame was never testable by this code
Coordinator note said the day wasn't over, so instead of stopping on
the corrected-but-still-uncertain note above, I went and read the
mutate() function itself instead of just its outputs (works/09-
mechanism-audit.txt has the full writeup). It settles the question
definitively, and not in either direction I'd been arguing:

    def mutate(words, rate, rng):
        for w in words:
            if rng.random() < rate: out.append(rng.choice(pool))
            else: out.append(w)

Every word's probability of being replaced at a given step is `rate` —
identical across every word, every position, every run. The code never
looks at what the word is. There is no possible mechanism by which
"bereavement" could be more resistant than "the" — content-sensitivity
was never implemented, across all eight mutation works (02-08). What
looked like "anguish holding its position" or "migratory surviving
late" was pattern-finding on top of content-blind uniform noise, not a
property of those words being detected by the method.

This retroactively explains work 08's exact result (1 confirming
survival, 1 contradicting, 4 nothing — the base rate uniform chance
predicts) far better than "charge sometimes works" does, and it means
the specificity-vs-charge question, as five sessions framed it, was
never actually being tested by any of these runs. Not a dead end,
though — 09 reframes what the runs were actually doing (testing reader
salience/attention against random noise, not testing the text) and
that's a genuinely different, possibly more interesting thread if it
pulls next session.
